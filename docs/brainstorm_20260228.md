## 案2: Transformer予測モデルの進化

### 1. BERT × Transformer Decoder の二段構成

ChatGPTでBERT modernモデルの話を聞いたことをきっかけに、エンコーダ（分類・理解）とデコーダ（予測・生成）の役割分担を検討。

**段階的アプローチ:**

- **Step 1（まずこれ）**: Transformer Decoder + Attention のみで予測
  - 言語モデルではなく、テーブルデータに対するAttention構造
  - FT-Transformer / TabNet 系のアプローチ
- **Step 2（改善軸）**: BERT系エンコーダを前段に追加
  - 人手で設計していたEmbeddingの部分をBERTが学習で獲得
  - 「どの特徴量が重要か」をBERT自身が発見する
  - Step 1との比較で効果量を測定 → note記事ネタにもなる

### 2. EM反復精錬（Iterative Mutual Refinement）

**核心アイデア**: 馬とコースの特徴量を交互に精錬していく

```
[Iteration 1] コース特徴（粗い） → 馬がどう走ったか学習
[Iteration 2] 馬の特徴（粗い）   → その馬がコースでどう走ったか学習
[Iteration 3] 馬の特徴（精錬済み）→ コース特徴の精度UP
[Iteration 4] コース特徴（精錬済み）→ 馬の特徴の精度UP
    ...繰り返し → 収束
```

**なぜこれが有効か:**

馬の強さはコースによって変わるし、コースの難しさは走る馬によって評価が変わる。鶏と卵の問題を、交互精錬で解決する（EMアルゴリズムに近い発想）。

**Transformerでの実装:**

- **Self-Attention**: 「コース同士の関係」「馬同士の関係」を学習
- **Cross-Attention**: 「馬とコースの関係」を学習
- 反復 = Transformerの層を重ねること自体が担う

```
コースEncoder ←Cross-Attention→ 馬Encoder
    ↕                                ↕
コース特徴量                      馬特徴量
```

**「イデア化」**: 反復精錬の到達点として、各馬の個性が純化される。個体としてのイデア馬（例: カナチャンスキー）が抽出される。コースも同様にイデアコースへ。

**実験計画:**

- 反復回数（1回, 2回, 4回, 8回...）と予測精度の関係を測定
- 収束するポイントの特定
- note記事: 「AIに馬とコースを交互に理解させたら、どんどん賢くなった」

### 3. 案1との合流ポイント

案1の物理モデルで得た知見（コース帯展開座標系、遠心力コスト等）を **コースEncoder側の初期特徴量** として入力可能。物理モデルとTransformerが自然に統合される。

## 騎手の扱い

### 問題意識

- 騎手を組み込むと馬×コース×騎手で組み合わせ爆発
- 本質的には馬とコースの関係を捉えたい（騎手はできれば無視したい）
- しかし統計的に勝率が偏る騎手がいる事実は無視できない

### 解決策: 上方補正のみモデル

**倫理的配慮**: 下位騎手を「マイナス要因」として名指しすることは人の尊厳を傷つける。書けない。

**設計方針:**

```
超優秀: +補正大（リーディングTOP数名）
優秀:   +補正小（上位安定組）
普通:   補正なし（それ以外全員）
```

- **マイナス補正は存在しない** → 誰も傷つけない
- カテゴリ分けの基準はリーディング順位（公式データ）→ 主観ではない
- 「優秀だから有名、有名だから依頼される」— 因果関係は追わず、観測された事実だけ使う

**実装:**

```
予測着順 = f(イデア馬, イデアコース, レース状況)  ← 本質のモデル
           + g(騎手カテゴリ)                       ← 上方補正のみ
```

**騎手評価方法:**

- 全レースデータから **馬を無視して** 騎手別着順分布だけを見る
- 統計的に有意に偏りがある騎手 = 超優秀 or 優秀
- 「有名だから強い馬に乗る」問題 → 無視する
  - 優秀だから有名、有名だから依頼される、どちらが先でも結果として補正すべき存在
  - 因果関係は追わず、観測された事実（この騎手は勝ちがち）だけを使う

**検証:**

- 予測A: 騎手補正なし
- 予測B: 騎手補正あり
- A vs B の差 = 騎手補正の効果量
- もし大して変わらなければ「やっぱり騎手はお飾りだった」という記事にもできる

**note記事での表現**: 「上位騎手の腕は数字に出る。それ以外は馬の力がそのまま結果に出る」
「このモデルの主役はあくまで馬とコース。騎手は最後にちょっと足すだけ」

## 案1: 物理モデルの改善

### 1. スタート・初速パラメータの導入

Active Matterモデルに初期条件の精度向上を追加。

**データソース:**

- 最初の1ハロン（200m）タイム → 初速指標
- テン3F（最初の600m）タイム → 立ち上がり加速傾向
- パトロールビデオからの定性分析（将来）

**モデルへの組み込み:**

- 初期速度パラメータ: 各馬のスタート能力を分布として保持（毎レースばらつきがある）
- 加速係数: 脚質（逃げ/先行/差し/追込）ごとの加速パターン

### 2. ベスト体重推定と乖離補正

**仮説**: 馬にはパフォーマンスが最大化する最適体重（ベスト体重）がある。

```
軽すぎ → パワー不足（筋量減少）
重すぎ → 負荷増大（運動効率低下）
ベスト → パワーと効率の最適バランス
```

**推定方法:**

- 各馬の過去全出走時体重 × 着順を回帰分析
- 二次関数（放物線）でフィット → 頂点がベスト体重
- 当日体重との差分を補正係数として使用

**エネルギー枯渇モデルとの統合:**

```
初期エネルギー = f(ベスト体重との乖離, 馬のバイタリティ)
初速・加速    = f(スタート巧拙, 脚質, ゲート番号)
エネルギー消費率 = f(速度, コース勾配, 馬場状態, 体重)
```

体重がベストから離れると初期エネルギーが減り、重いと消費率も上がる。物理的に自然な形で組み込める。

### 3. 可視化の二段構え

**課題**: 帯展開でX軸をスタート→ゴール距離にすると、時間が表現できない

**解決策A: スペースタイムダイアグラム（静止画）**

```
距離(Y軸)↑
ゴール |----●---●----●------  ← ゴール到達順 = 着順
       |   /   /    /
       |  /  /   /
       | / /  /
スタート|///__________________→ 時間(X軸)
```

- 速い馬は急角度で上に向かう → 視覚的にわかりやすい
- ペース変化、エネルギー枯渇ポイントが一目でわかる
- note記事のメイン図として使用

**解決策B: アニメーション（GIF）**

- 帯展開コース上を馬が動く
- インアウト・馬群の圧・密集具合の表現が可能
- 走行圧シミュレーションの真価を見せる

**note記事での使い分け:**

- スペースタイムダイアグラムで「結果はこう」→ アニメGIFで「中身はこう動いてた」
- 静止画で「おっ」→ アニメで「おおお！」の二段構え
- 読み応え × わかりやすさの両立
