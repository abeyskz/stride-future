# 🔬 4つの予測アプローチ

## 案1：数式モデルによる物理シミュレーション（ホワイトボックス）🏇

**表で検証**

競馬を「個体（馬）の運動」と「集団（馬群）の相互作用」の系として捧え、数式でレースを再現する。

中核仮説：馬群を粒子集合（流体的）として扱い、各馬が受ける「走行圧」を積分評価。走行圧が小さい（進路が開ける／不利な干渉が少ない）個体が好走しやすい。

- 理論背景：群集流体力学、粒子相互作用モデル、相転移・ボトルネック流量、経路最適化
- 入力データ：コース形状、頭数・枠順、脚質・先行力の近似、ペース構成の近似
- 出力：各馬の「不利度（走行圧）」スコア → 上位3頭の推定
- 長所：説明可能、仮説検証がしやすい
- 短所：パラメータ設計が重い／未知要因（気性・展開の揺れ）に弱い

## 案2：コース特性分離 Transformer 予測（生成AI系の基盤技術を応用）🧠

**表で検証**

### 0) ねらい（この案が解くべき課題）

競馬の難しさは「馬の実力（個体差）」と「当日の環境（コース・馬場・展開）」が観測結果（着順・タイム）に混ざってしまう点にある。

案2は以下をモデル内部表現（embedding）として分離し、Attentionにより「どの関係が効いたか」をデータから学習して上位3頭を予測する。

- **能力成分**：馬の地力・適性
- **コース特性成分**：競馬場×コース×距離のクセ
- **当日状態成分**：馬場・天候・枠・斜量など

> Transformer は GPT などの生成AIにも使われる Attention 構造と同系統。
> 

> ただし本件は文章生成ではなく「レース内の関係性（相互作用）」を学習するランキング問題として使う。
> 

### 1) 入力設計

**1.1 レース単位（共通）の入力**

- レースID、開催日、競馬場、コース種別（芝/ダート）、距離
- 右左回り・内外回り（取得可能なら）
- 馬場状態（良/稍重/重/不良）、天候、出走頭数

**1.2 出走馬ごとの入力（エントリ単位）**

- 馬ID、騎手ID、枠番、斜量、年齢・性、当日馬体重/増減

**1.3 過去走（履歴）入力（時系列）**

馬の能力を直接数値化せず、過去走の観測を系列として入れる。

- 直近 N 走（推奨：まず **N=5**）
- 各過去走：日付、競馬場/芝ダ/距離、馬場状態、着順、通過順位、上がり3F、走破タイム、斜量、騎手

> 履歴を N=10 にすると表現力は増えるが、学習コストが急増。連載スケジュール優先なら N=5 から開始し、余裕が出たら拡張。
> 

### 2) 表現設計（embedding：分離の核心）

**コースIDの粒度（推奨）**

コース×距離（芝/ダ含む）を基本とする。

例：「中京×芝×1200」「中京×ダ×1800」

理由：コースのクセは距離で変わる、説明がしやすい（note向き）、学習した embedding が解釈しやすい

**主要 embedding**

- `E_horse`：馬ID embedding（個体の潜在表現）
- `E_jockey`：騎手ID embedding
- `E_course`：コースID embedding（競馬場×芝ダ×距離）
- `E_track`：馬場状態 embedding（良/稍/重/不良）
- `E_weather`：天候 embedding
- `E_frame`：枠番 embedding（または枠五行 embedding）

**未知ID（新馬・乗り替わり等）への対策**

- OOV（未知）用 embedding を用意
- ID embedding に加えてメタ特徴（年齢・性・斜量等）を MLP で埋め込み、未知IDでも最低限の表現を作れるようにする（cold-start耐性）

### 3) モデル構造：2段Transformer

**3.1 Horse History Encoder（馬ごとの履歴エンコーダ）**

- 入力：各馬の過去走系列（N走）
- Transformer Encoder（または軽量な Self-Attention）で系列をエンコード
- 出力：`H_horse`（馬の状態ベクトル）
- 直感：「この馬は近走どんな走りをしているか」「どの過去走が今回に効くか」を Attention が選ぶ

**3.2 Race Interaction Encoder（レース内相互作用エンコーダ）**

- 入力：各馬の `H_horse` に当日条件 embedding（騎手・枠・斜量・コースなど）を加えたトークン列
- Transformer Encoder で「同一レース内の馬同士の関係」を学習
- 出力：各馬の `R_horse`（レース文脈を含んだスコア用ベクトル）
- 直感：「このメンバー構成だと誰が有利か」「逃げが多い/差しが多い等の暗黙の展開」を相互参照で表現

> GPT が“単語同士の関係”を見るのと同様に、本モデルは“馬同士・馬×コース・馬×騎手”の関係を見る。
> 

### 4) 出力（予測タスク）

**4.1 ランキング用スコア**

- 各馬にスカラー `s_i` を出力、降順に並べて Top3 を提案

**4.2 学習ターゲット（推奨：2段階）**

- **Phase A（安定）：複勝分類（3着内=1／それ以外=0）**
    - 出力：`P(place)` を推定、上位3頭を提案
- **Phase B（本命）：ランキング学習（NDCG@3最適化）**
    - 1着=60、2着=30、3着=10、着外=0 を利得としてペアワイズ/リストワイズ損失で学習

> まずPhase Aで動くものを作り、Phase Bに移行するのが最短。
> 

### 5) 解釈性（ブラックボックスを“構造化”して読む）

Transformerはブラックボックスになりがちだが、以下で“読める”形に寄せる。

- Attention 重みの可視化（どの要素を見て判断したか）
- 重要特徴の推定（Permutation importance / SHAP 等）
- embedding の近傍探索（似たコース、似た馬のクラスタ）

note上では、「Attentionがどの履歴レースを参照したか」「コースembeddingが似ているコース群」などを図で出すと説得力が高い。

### 6) 五行（案4）との接続：外生特徴量として足す

五行は「占い」ではなく外生的特徴量。案2では五行由来の特徴を embedding として追加し、効くなら重みが付き、効かなければゼロに落ちるようにする。

入れ方（例）：

- `E_day5`：レース日の五行
- `E_frame5`：枠の五行（先天八卦）
- `E_horse5`：馬の誕生日由来の五行
- `E_jockey5`：騎手の誕生日由来の五行
- 相性特徴（相生/比和/相剋）を -1/0/+1 で符号化したものも embedding 化

> 五行の“重み付け”は固定しない。モデルが学習で決める。
> 

### 7) 実装メモ（最短で動かすための推奨パラメータ）

- 履歴長：N=5
- embedding次元：64〜128
- Transformer層数：2〜4（まず2）
- Attention head：4〜8
- 最適化：AdamW
- 正則化：dropout + weight decay
- GPU（RTX 5070 Ti）前提でまずは「検証が回ること」を優先

### 8) 成功判定

- 人気順Top3より Winner-in-Top3 が改善する
- または人気順Top3と同等でも NDCG@3 が改善して「並び」が良くなる

> 競馬は人気が強いので、いきなり人気を超えなくてもOK。まずは「補助モデルとして価値がある」ことを数値で示す。
>

## 案3：遺伝的アルゴリズム × 決定木（創発型）🧬

**裏で検証**

予測ルールそのものを進化させる探索。

- 個体＝決定木（条件分岐）
- 適応度＝予測ランキングの質（例：NDCG@3など）
- 交叉・突然変異でルールを創発

遺伝子構造例：

```
if 枠番 <= 3 and 馬体重増 > 10kg → +0.3
if 上がり3F < 33.5 → +0.5
if 中京経験なし → -0.2
```

評価関数： `fitness = Σ(実順位 - 予測順位)` → 「近づくほど良い」思想でOK。符号・スケーリングを統一して進化を安定させる。

- 長所：人間が思いつかないルール発見／決定木なので説明しやすい
- 短所：過学習しやすい（学習/検証分割が必須）

## 案4：五行説（外生特徴量としての“相性”）☯️

**裏で検証**

### 位置づけ

「占い」ではなく、五行を馬の能力とは無縁な“外生的（外部起因）特徴量”として扱う。当たるかどうかはデータが決める。効かなければ重みはゼロ（統計的に消える）。

### 五行化対象

- **レース日**：日干支→五行
- **枠番**：先天八卦（1〘8）→五行
- **馬**：生年月日→日干支→五行
- **騎手**：生年月日→日干支→五行

### 枠番→先天八卦→五行（確定方針）

1=乾(金) / 2=兌(金) / 3=離(火) / 4=震(木) / 5=巽(木) / 6=坎(水) / 7=艮(土) / 8=坤(土)

### 相性の符号化

- 相生（A→Bが生む）= +1
- 比和（同じ）= 0
- 相剋（A→Bが剋す）= -1

> 重み付けは固定しない。機械学習で推定する。
>

# 📊 評価ルール（最終確定）

評価は **NDCG@3** と **Winner-in-Top3** の2軸で行う。

## 1) Winner-in-Top3（勝ち馬拾い）

- 予想Top3に実際の1着馬が含まれる → 1
- 含まれない → 0

直感的で、読者にも説明しやすい。

## 2) NDCG@3（ランキングの質）

予想した上位3頭の並びが、どれだけ「良い順位付け」かを評価。

利得（gain）：1着=60、2着=30、3着=10、着外=0

思想：**「1着を当てるのが競馬の本質。でもちょっとした誤差で2位3位になったのは拾ってあげる」**

> note上では「ランキング評価（NDCG@3）と、勝ち馬拾い（Winner-in-Top3）」とだけ書けば十分。
> 

## 3) ベースライン（必須）

比較対象が無いと結果が評価しづらいので最低2つ置く：

- **人気順Top3**（強力な基準）
- **ランダムTop3**（下限）

- 短所：パラメータ設計が重い／未知要因（気性・展開の揺れ）に弱い

## 案2：コース特性分離 Transformer 予測（生成AI系の基盤技術を応用）🧠

### 0) ねらい（この案が解くべき課題）
競馬の難しさは「馬の実力（個体差）」と「当日の環境（コース・馬場・展開）」が**観測結果（着順・タイム）に混ざってしまう**点にある。

案2は、以下を満たすことを目的とする。

- **能力成分**（馬の地力・適性）と
- **コース特性成分**（競馬場×コース×距離のクセ）と
- **当日状態成分**（馬場・天候・枠・斤量など）

を、モデル内部表現（embedding）として分離し、
**Attention により「どの関係が効いたか」をデータから学習**して、上位3頭を予測する。

> 重要：ここでいう Transformer は GPT などの生成AIにも使われる Attention 構造と同系統。
> ただし本件は文章生成ではなく **「レース内の関係性（相互作用）」を学習するランキング問題**として使う。

---

### 1) 入力設計（何をモデルに食わせるか）

#### 1.1 レース単位（共通）の入力
- レースID
- 開催日（レース日）
- 競馬場（例：中京）
- コース種別（芝/ダート）
- 距離
- 右左回り、内外回りなど（取得可能なら）
- 馬場状態（良/稍重/重/不良）
- 天候
- 出走頭数

#### 1.2 出走馬ごとの入力（エントリ単位）
- 馬ID（※新馬など未知の場合の扱いは後述）
- 騎手ID
- 枠番（先天八卦→五行も後段で特徴量化可能）
- 斤量
- 年齢・性
- 当日馬体重 / 増減（取得できる範囲で）

#### 1.3 過去走（履歴）入力（時系列）
「馬の能力」を直接数値化するのではなく、**過去走の観測**（成績・ラップなど）を系列として入れる。

- 直近 N 走（推奨：まず **N=5**）
- 各過去走について
  - 日付
  - 競馬場 / 芝ダ / 距離
  - 馬場状態
  - 着順、通過順位（あれば）
  - 上がり3F
  - 走破タイム（補正タイムでも可）
  - 斤量
  - 騎手（乗り替わりの変化を拾うため）

> 履歴を N=10 にすると表現力は増えるが、学習コストが急増する。
> 連載スケジュール優先なら N=5 から開始し、余裕が出たら拡張。

---

### 2) 表現設計（embedding：分離の核心）

#### 2.1 コースIDの粒度（推奨）
**コース×距離**（さらに芝/ダ含む）を基本とする。

例：
- 中京 × 芝 × 1200
- 中京 × ダ × 1800

理由：
- コースのクセは距離で変わる（同一競馬場でも別物）
- 説明がしやすい（note向き）
- 学習した embedding が「コース特性」として解釈しやすい

#### 2.2 主要embedding
- `E_horse`：馬ID embedding（個体の“潜在表現”）
- `E_jockey`：騎手ID embedding
- `E_course`：コースID embedding（競馬場×芝ダ×距離）
- `E_track`：馬場状態 embedding（良/稍/重/不良）
- `E_weather`：天候 embedding
- `E_frame`：枠番 embedding（または枠五行 embedding）

#### 2.3 未知ID（新馬・乗り替わり等）への対策
- OOV（未知）用 embedding を用意
- 可能なら ID embedding に加えて **メタ特徴**（年齢・性・斤量など）を MLP で埋め込み、
  未知IDでも最低限の表現を作れるようにする（cold-start耐性）

---

### 3) モデル構造（2段Transformer：おすすめ構成）

案2の「分離」を保ちながら精度を出すため、構造は大きく2段に分ける。

#### 3.1 Horse History Encoder（馬ごとの履歴エンコーダ）
- 入力：各馬の過去走系列（N走）
- Transformer Encoder（または軽量な Self-Attention）で系列をエンコード
- 出力：`H_horse`（馬の状態ベクトル）

直感：
- 「この馬は近走どんな走りをしているか」
- 「どの過去走が今回に効くか」を Attention が選ぶ

#### 3.2 Race Interaction Encoder（レース内相互作用エンコーダ）
- 入力：各馬の `H_horse` に、当日条件 embedding（騎手・枠・斤量・コースなど）を加えたトークン列
- Transformer Encoder で **“同一レース内の馬同士の関係”**を学習
- 出力：各馬の `R_horse`（レース文脈を含んだスコア用ベクトル）

直感：
- 「このメンバー構成だと誰が有利か」
- 「逃げが多い/差しが多い等の暗黙の展開」を相互参照で表現する

> 重要：ここが GPT 的な Attention の本領。
> 言語モデルが“単語同士の関係”を見るのと同様に、
> 本モデルは“馬同士・馬×コース・馬×騎手”の関係を見る。

---

### 4) 出力（予測タスク）

#### 4.1 まずは「ランキング用スコア」を出す
- 各馬にスカラー `s_i` を出力
- `s_i` の降順に並べて Top3 を提案

#### 4.2 学習ターゲット（推奨：2段階）
連載スケジュールを考えると、まずは安定するところから。

**Phase A（安定）：複勝分類（3着内=1/それ以外=0）**
- 出力：`P(place)` を推定
- Top3：`P(place)` 上位3頭

**Phase B（本命）：ランキング学習（NDCG@3最適化）**
- 1着=60、2着=30、3着=10、着外=0 を利得として
- ペアワイズ/リストワイズ損失で「上位に置くべき馬」を学ぶ

> まずPhase Aで動くものを作り、Phase Bに移行するのが最短。

---

### 5) 評価（本プロジェクトの確定指標）

- **Winner-in-Top3**：予想Top3に実際の1着が入っているか
- **NDCG@3**：Top3の並びの質（利得：60/30/10/0）

補助（裏で見ると便利）：
- 人気順Top3との比較（強ベースライン）
- ランダムTop3との比較（下限）

---

### 6) 解釈性（ブラックボックスを“構造化”して読む）
Transformerはブラックボックスになりがちだが、以下で“読める”形に寄せる。

- Attention 重みの可視化（どの要素を見て判断したか）
- 重要特徴の推定（Permutation importance / SHAP 等）
- embedding の近傍探索（似たコース、似た馬のクラスタ）

note上では、
- 「Attentionがどの履歴レースを参照したか」
- 「コースembeddingが似ているコース群」

などを図で出すと説得力が高い。

---

### 7) 五行（案4）との接続：外生特徴量として足す
五行は「占い」ではなく **外生的特徴量**。

案2では、五行由来の特徴を **embedding** として追加し、
効くなら重みが付き、効かなければゼロに落ちるようにする。

入れ方（例）：
- `E_day5`：レース日の五行
- `E_frame5`：枠の五行（先天八卦）
- `E_horse5`：馬の誕生日由来の五行
- `E_jockey5`：騎手の誕生日由来の五行
- 相性特徴（相生/比和/相剋）を -1/0/+1 で符号化したものも embedding 化

> 重要：五行の“重み付け”は固定しない。モデルが学習で決める。

---

### 8) 実装メモ（最短で動かすための推奨パラメータ）

- 履歴長：N=5
- embedding次元：64〜128
- Transformer層数：2〜4（まず2）
- Attention head：4〜8
- 最適化：AdamW
- 正則化：dropout + weight decay

GPU（RTX 5070 Ti）前提なら、
- バッチサイズはメモリと相談（小さくても学習は回る）
- まずは学習時間より「検証が回ること」を優先

---

### 9) 成功判定（この仮説が勝つ条件）

- 人気順Top3より **Winner-in-Top3** が改善する
- もしくは人気順Top3と同等でも、**NDCG@3** が改善して「並び」が良くなる

> 競馬は人気が強いので、いきなり人気を超えなくてもOK。
> まずは「補助モデルとして価値がある」ことを数値で示す。

## 案3：遺伝的アルゴリズム × 決定木（創発型）🧬

### 概要
**予測ルールそのものを進化させる**探索。

- 個体＝決定木（条件分岐）
- 適応度＝予測ランキングの質（例：NDCG@3など）
- 交叉・突然変異でルールを創発

### 遺伝子構造（例）

```text
if 枠番 <= 3 and 馬体重増 > 10kg → +0.3
if 上がり3F < 33.5 → +0.5
if 中京経験なし → -0.2
```

### 評価関数（候補）
- 近さを評価する：順位誤差、Spearman、あるいは **NDCG@3**

> もともとの `fitness = Σ(実順位 - 予測順位)` は「近づくほど良い」思想でOK。
> ただし符号やスケーリングを統一して、進化が安定するようにする。

### 長所 / 短所
- 長所：人間が思いつかないルール発見／決定木なので説明がしやすい
- 短所：過学習しやすい（学習/検証分割が必須）

## 案4：五行説（外生特徴量としての“相性”）☯️

### 位置づけ（重要）
本プロジェクトでは **「占い」ではなく**、
五行を **馬の能力とは無縁な“外生的（外部起因）特徴量”** として扱う。

- *当たるかどうか* はデータが決める
- 効かなければ重みはゼロ（統計的に消える）

### 何を五行化するか（例）
- **レース日**：日干支→五行
- **枠番**：先天八卦（1〜8）→五行
- **馬**：生年月日→日干支→五行（能力情報を入れない）
- **騎手**：生年月日→日干支→五行

### 枠番→先天八卦→五行（確定方針）
先天八卦を番号に対応させる（美しくハマる版）：
- 1 乾=金
- 2 兌=金
- 3 離=火
- 4 震=木
- 5 巽=木
- 6 坎=水
- 7 艮=土
- 8 坤=土

### 相性の符号化（最初はシンプルに）
- 相生（A→Bが生む） = +1
- 比和（同じ） = 0
- 相剋（A→Bが剋す） = -1

> **重み付けは固定しない**。機械学習で推定する。

# 📊 評価ルール（最終確定：研究に耐える指標）

> **結論**：評価は **NDCG@3** と **Winner-in-Top3** の2軸で行う。

## 1) Winner-in-Top3（勝ち馬拾い）
- 予想Top3の中に **実際の1着馬が含まれる** → 1
- 含まれない → 0

直感的で、読者にも説明しやすい。

## 2) NDCG@3（ランキングの質）
- 予想した上位3頭の並びが、どれだけ「良い順位付け」かを評価

利得（gain）はあなたの設計を採用：
- 1着=60、2着=30、3着=10、着外=0

`DCG@3` を計算し、理想配置で正規化して `NDCG@3` を得る（0〜1）。

> note上では「ランキング評価（NDCG@3）と、勝ち馬拾い（Winner-in-Top3）」とだけ書けば十分。

## 3) ベースライン（必須）
比較対象が無いと結果が評価しづらいので最低2つ置く：
- **人気順Top3**（強力な基準）
- **ランダムTop3**（下限）
