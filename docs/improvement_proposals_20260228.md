## 🧠 案2：Transformer予測の改善

### 改善1: 反復的相互精錬（EM的アプローチ）

#### コンセプト

馬の特徴量とコースの特徴量を**交互に精錬**していくことで、相互の理解精度を高める。
EMアルゴリズム（Expectation-Maximization）に着想を得たアプローチ。

#### 精錬プロセス

```
[Iteration 1] コース特徴（粗い）→ 馬がどう走ったかを学習
[Iteration 2] 馬の特徴（粗い）  → その馬がコースでどう走ったかを学習
[Iteration 3] 馬の特徴（精錬済）→ コース特徴の精度UP
[Iteration 4] コース特徴（精錬済）→ 馬の特徴の精度UP
    ...繰り返し...
→ 馬×コースの相互理解が収束 = 「イデア化」
```

#### なぜ有効か

- **鶏と卵の問題を解決**: 馬の強さはコースによって変わるし、コースの難しさは走る馬によって評価が変わる。どちらかを先に固定すると偏るが、交互に精錬すると両方の精度が上がる
- 収束後の馬の表現は、個性が純化された「イデア馬」（例：カナチャンスキー）となる
- コースも同様に「イデアコース」として純化される

#### Transformerでの実装

**Cross-Attention**がこの相互参照を自然に実現する。

```
コースEncoder ←── Cross-Attention ──→ 馬Encoder
    ↕                                      ↕
コース特徴量                            馬特徴量
```

- **Self-Attention**: コース同士の関係、馬同士の関係を学習
- **Cross-Attention**: 馬とコースの相互関係を学習
- **反復**: Transformerの層を重ねること自体が反復精錬を担う

#### 実験設計

| 実験 | 構成 | 目的 |
|------|------|------|
| Baseline | コース→馬の1回のみ | 既存設計のベースライン |
| EM-2 | 2回反復（コース→馬→コース→馬） | 反復効果の初期確認 |
| EM-4 | 4回反復 | 収束傾向の確認 |
| EM-N | 反復回数をハイパーパラメータ化 | 最適反復回数の探索 |

→ 反復回数と精度の関係をグラフ化し、note記事のネタにもする

### 改善2: BERT系エンコーダの段階的導入

#### 方針

**Step 1（まず実装）**: Transformer Decoder + Attention のみで予測

```
テーブルデータ → Embedding層 → Transformer Decoder → 着順予測
                                (Self-Attention)
                                     ↕
                                教師信号（実着順）
```

**Step 2（改善軸として）**: BERT系エンコーダを前段に追加

```
テーブルデータ → BERT系エンコーダ → リッチなEmbedding → Transformer Decoder → 予測
                (特徴量の関係性を
                 双方向で学習)
```

#### 狙い

- Step 1では人手で設計するEmbeddingの部分を、Step 2ではBERTが学習で獲得
- 「どの特徴量が重要か」をBERT自身が発見する可能性
- note記事で「GPTだけ vs BERT+GPT」→「Transformer Decoder のみ vs BERT Encoder + Decoder」の比較が読み応えある

#### 重要な注記

- ここでいう「GPT系」「BERT系」は**言語モデルではない**
- Transformerアーキテクチャのデコーダ部分（自己回帰的予測）とエンコーダ部分（双方向文脈理解）を、テーブルデータに対して適用するもの
- FT-Transformer、TabNet等の先行研究と同じ系譜

```
[EM反復精錬]
```

## 🏇 案1：物理モデルの改善

### 改善1: スタート巧拙・初速パラメータの導入

#### 背景

シミュレータモデルにおいて、馬のスタート（ゲート出）の巧拙と立ち上がり初速は着順に直接影響する要素。現在のモデルではこのパラメータが未考慮。

#### データソース

| パラメータ | データの取得元 | 指標 |
|-----------|--------------|------|
| ゲート出の反応時間 | 最初の計測ポイントまでの区間タイム | スタート速度 |
| 初速（テン1F） | 最初の200mのタイム | 加速力 |
| 立ち上がり加速（テン3F） | 最初の600mのタイム | 加速の持続性 |

#### Active Matterモデルへの組み込み

- **初期速度パラメータ**: 各馬のスタート時の速度 v₀
- **加速係数**: ゲートからの立ち上がり加速度 a₀
- **スタート偏差**: 同じ馬でも毎回異なるため、分布（平均±標準偏差）で保持

```
v(t=0) = v₀ + ε    （ε ∼ N(0, σ²_start)）
a(t<T_accel) = a₀ × (1 - v(t)/v_max)
```

### 改善2: ベスト体重推定と乖離補正

#### 仮説

各馬にはパフォーマンスを最大化する「ベスト体重」が存在する。
ベスト体重から離れるほど（軽すぎても重すぎても）パフォーマンスが低下する。

```
軽すぎ → パワー不足（筋量減少）→ 推進力F_propulsionの低下
重すぎ → 負荷増大（運動効率低下）→ エネルギー消費率の増加
ベスト → パワーと効率の最適バランス
```

#### 推定方法

EDAの162万行データに含まれる馬体重と着順から：

```
各馬の全出走データ: (体重_i, 着順_i) のペア
→ 二次関数フィット: performance = -α(weight - W_best)² + β
→ W_best = ベスト体重の推定値
```

#### エネルギー枯渇モデルへの統合

```
初期エネルギー E₀ = f(ベスト体重との乖離, 馬のバイタリティ)
  → |W_actual - W_best| が大きいほど E₀ が減少

エネルギー消費率 dE/dt = f(速度, コース勾配, 馬場状態, 体重)
  → W_actual が大きいほど消費率UP

初速・加速 = f(スタート巧拙, 脚質, ゲート番号)
```

体重がベストから離れると初期エネルギーが減り、さらに重いと消費率も上がる二重のペナルティ。

### 改善3: 可視化の二段構え

#### 3a: スペースタイムダイアグラム（静止画）

```
距離(Y軸)↑
ゴール   |----●---●----●------  ← ゴール到達順 = 着順
         |   /   /    /
         |  /  /   /
         | / /  /
スタート |///__________________→ 時間(X軸)
```

- **X軸**: 経過時間
- **Y軸**: スタートからの距離
- 各馬が線（軌跡）として描かれる
- ゴールライン（Y=距離）を最初に横切った馬が1着
- **用途**: 着順判定、ペース変化、エネルギー枯渇ポイントの可視化
- **note記事のメイン図**として使用

#### 3b: アニメーション（GIF/動画）

- 帯展開コース上を馬が動くアニメーション
- インアウトの位置関係、馬群の圧力、密集度が視覚的に伝わる
- **圧シミュレーションの真価**を見せるのはこちら

#### 記事での使い分け

1. スペースタイムダイアグラムで「結果はこう」を静止画で提示
2. アニメGIFで「中ではこう動いていた」を動的に説明
3. 読者は「おっ」→「おおお！」の二段階で引き込まれる

## 🏆 騎手の扱い：上方補正モデル

### 方針

- **馬とコースの本質を捉えることが主目的**。騎手は外部要因として扱う
- マイナス補正は行わない（個人の尊厳への配慮）
- 上位騎手のプラス補正のみ適用

### カテゴリ分類

| カテゴリ | 補正 | 基準 |
|---------|------|------|
| 超優秀 | +補正大 | リーディングTOP数名 |
| 優秀 | +補正小 | 上位安定組 |
| 普通 | 補正なし | それ以外全員 |

### 分類手法

- 全レースデータから**馬を無視して**騎手別の着順分布だけを見る
- 統計的に有意な偏り（勝率が高い）がある騎手 = 超優秀 or 優秀
- 「有名だから強い馬に乗る」問題は無視する
  - 理由: 優秀だから有名、有名だから依頼される。因果関係を追わず、観測された事実（この騎手は勝ちがち）だけを使う

### 適用方法

```
予測着順 = f(イデア馬, イデアコース, レース状況)  ← 本質のモデル
           + g(騎手カテゴリ)                      ← 上方補正のみ
```

### 検証

| 実験 | 構成 | 目的 |
|------|------|------|
| A | 騎手補正なし | 純粋な馬×コースモデルの実力 |
| B | 騎手補正あり | 補正の効果量の測定 |

→ AとBの差 = 騎手補正の効果量
→ 差が小さければ「やはり主役は馬とコース」と結論できる

### note記事での表現

> 「このモデルの主役はあくまで馬とコース。騎手は最後にちょっと足すだけ。」
> 「上位騎手の腕は数字に出る。それ以外は馬の力がそのまま結果に出る。」

## 📊 案1 × 案2 の合流ポイント

| 案1の出力 | 案2での利用 |
|-----------|-----------|
| 走行圧スコア | コースEncoder側の特徴量 |
| エネルギー枯渇推定 | 馬Encoder側の特徴量 |
| 帯展開座標系の距離補正 | コース特徴の初期値 |
| ベスト体重乖離 | 馬の状態特徴量 |

→ 物理モデルが「解釈可能な特徴量」を生成し、Transformerがそれを含む全特徴量から「予測」を行う
